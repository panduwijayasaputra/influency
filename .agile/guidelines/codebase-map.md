> Overview of what currently exists in Influency. Keep in sync when adding modules, models, endpoints or routes (`/dev-team` updates this when a story completes).

**Patterns established:**
- ESM everywhere; relative imports in api/shared use `.js` suffixes.
- Tests: Vitest. API tests boot the real app via `createApp({ logger: false })` and use Fastify `app.inject()`. To override providers (e.g. `PrismaService`), build with `Test.createTestingModule(...).overrideProvider(...)`, then `createNestApplication(createFastifyAdapter({ logger: false }))` + `configureApp(app)`. Test-only controllers follow `common/errors.spec.ts`. `vitest.config.ts` sets a placeholder `DATABASE_URL` (never contacted). Web tests use Testing Library + jsdom.
- Errors: throw `DomainError(code, details?)`; codes/statuses/messages in `ERRORS` (`packages/shared/src/errors.ts`). Every error body is `{ error: { code, message, requestId, details } }`; unknown errors → 500 `INTERNAL_ERROR`. Validate input with `new ZodValidationPipe(schema)`.
- Request ID: `X-Request-Id` on every response (incoming reused if `/^[A-Za-z0-9_-]{1,64}$/`, else `req_<uuid>`); same value as `requestId` in pino logs and error bodies. Request logs record the path without query string.
- Database: inject `PrismaService` (global). Lazy connection — the API boots with the DB down. Schema conventions (uuidv7 UUID PKs, `Timestamptz(3)`, snake_case via `@map`, integer money) are enforced by `src/common/schema-conventions.integration.spec.ts`.
- Integration tests: `*.integration.spec.ts`, `createTestPrisma()` from `apps/api/test/prisma.ts`, against the shared `TEST_DATABASE_URL` DB (wiped + migrated once per `vitest run`; must end in `_test`). Specs that write rows use their own fixed ids or clean up. Specs run in parallel on one DB, so fixed ids must not collide: grep `0190a000-0000-7000-8000-0000001` for the ranges in use (`1a` creator-profile, `1b` public-profile, `1c` posts, `1d` post-media, `1e` post-media-video, `1f` post-offers, `20` post-publish, `21` public-posts, `22` creator-application-reviews-schema, `23` post-access, `24` post-cover + public-post-preview, `14` public-post-detail, `26` media-cleanup, `27` video-webhook, `28` post-likes, `29` post-comments, `2a` post-comment-replies, `2b` comment-likes, `2c` post-comment-edit, `2d` post-comment-pin, `2e` post-comment-moderation) and take the next one. A spec calling the global `PostMediaService.sweep(now)` must keep its stale rows earlier than any other spec stores (media-cleanup uses 1965; other specs use `new Date(0)`).
- Seed: add an idempotent step to `seedSteps` (`prisma/seed/seed.ts`), referencing fixed ids in `src/common/demo-ids.ts` (`DEMO_USER_IDS`, `DEMO_CREATOR_PROFILE_IDS`). `pnpm db:reset` / `db:seed` / `db:migrate` from the root.
- Post lifecycle (US-019, US-047): `POST_EDITABLE_STATUSES` (DRAFT only since US-047) / `isPostEditable` (shared); PUBLISHED → ARCHIVED → PUBLISHED via archive/restore, each in one transaction that also opens/closes a `post_archive_episodes` row. **Purchases (US-025) must require `status = PUBLISHED`** — that is what makes an archived post unsellable; US-050 reads the open episode's `archived_at` for archive grants. Anything that changes visibility or media takes the post-row lock (`lockPost` in `posts.service.ts`, `lockEditablePost` in `post-media.service.ts`) or a conditional write on status, so publish checks can't be bypassed. Public post data goes through `GET /creators/:slug/posts` and `GET /creators/:slug/posts/:postId` only (counts + offer terms, never media refs; shared `publicPostFields` mapping in `public-posts.service.ts`).
